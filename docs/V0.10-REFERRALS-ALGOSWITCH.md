# Minewhile v0.10

## Beneficiary / referral

Without referral:

    USER      90%
    OPERATOR  10%

With referral:

    USER         90%
    BENEFICIARY   5%
    OPERATOR      5%

The referral reward comes entirely from the Minewhile/operator share.
Minewhile should not maintain custodial balances.

A beneficiary may represent an influencer, website, project, community or other recipient.

Planned model:

    /?r=ABCDEFGH

The browser stores first-party attribution.
The server remains authoritative for beneficiary payout wallet and currency.

Management uses a high-entropy secret rather than an account/password system.

## Algorithm switching

Current regression baseline:

    YesPower 1.0
    N=2048
    r=32
    personalization=NULL

A generic WASM entry point, yp_hash_params(), allows the relay/browser protocol
to select YesPower parameters without replacing the proven standard path.

Initial algorithm catalog includes:

    yespower
    yespowerTIDE
    yespowerR16
    yespowerURX
    yespowerADVC
    yespowerLTNCG
    yespowerSUGAR

Future scheduler score should consider:

    browser benchmark H/s per algorithm
    pool profitability
    current Minewhile allocation
    network impact
    stability / hysteresis

The scheduler must not move the entire fleet into a small network merely
because it temporarily reports the highest profitability.
